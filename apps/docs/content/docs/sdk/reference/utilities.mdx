## Name

### `Name.dnsDecode`

Name from its DNS wire-format encoding, as returned by ENSv2 registries and the Universal


### `Name.normalize`

Normalizes an ENS name (ENSIP-15).

```ts
function normalize(name: string): string
```

- `""` is the root name and is returned as-is.
- Uses viem's ENSIP-15 normalizer (ENSIP-15 rejects alternative full stops such as `。`).
- Encoded labels such as `[af2c…]` (64 hex digits) are kept, so names from indexers round-trip.

```ts title="Normalizing user input"
import { Name } from "@ensforge/sdk"

Name.normalize("Nick.ETH") // "nick.eth"
```

Errors:

- `InvalidInputError` ([`INVALID_NAME`](/docs/sdk/errors/INVALID_NAME)) when a label cannot be normalized.

### `ContentHash.toGatewayUrl`


```ts title="Using the client's gateways"
import { ContentHash } from "@ensforge/sdk"
```

## Errors

### `Errors.describe`

Turns any thrown value into a title, message and suggested action that are safe to show users.

```ts
function describe(value: unknown, options: DescribeOptions = {}): Description
```

Use in UI error handlers instead of showing `error.message`, which is written for developers.

- Accepts any value; non-ensforge errors go through `Errors.fromCause` first.
- Override copy per code with `messages`, for example to translate.

```ts title="Showing an error toast"
import { Errors } from "@ensforge/sdk"

try {
  await ens.record.set({ name: "alice.eth", texts: { url: "https://alice.dev" } })
} catch (error) {
  const { title, message, action } = Errors.describe(error)
  toast({ title, description: action === undefined ? message : `${message} ${action}` })
}
```

```ts title="Translating one code"
import { Errors } from "@ensforge/sdk"

Errors.describe(error, {
  messages: { NAME_NOT_AVAILABLE: (e) => ({ title: "Nombre no disponible", message: `${e.context.name} ya está registrado.` }) },
})
```

### `Errors.fromCause`

Translates any thrown value into an ensforge error and adds `context`.

```ts
function fromCause(cause: unknown, context?: EnsforgeError.Context): EnsforgeError
```

Use when calling viem directly next to ensforge actions, to get the same error classes, codes
and `Errors.describe` messages. Every ensforge action already does this.

- ensforge errors are returned as-is, with `context` merged in.
- viem errors are matched along their `cause` chain; contract reverts are decoded against every
  ENS contract error, unwrapping `ResolverError` and the mainnet `ResolutionError`.
- Anything else becomes `InternalError` ([`UNEXPECTED`](/docs/sdk/errors/UNEXPECTED)) with the original as `cause`.

```ts title="Translating a viem error"
import { Errors } from "@ensforge/sdk"

try {
  await walletClient.writeContract(request)
} catch (cause) {
  const error = Errors.fromCause(cause, { operation: "custom.write" })
  toast(Errors.describe(error).title)
}
```

### `Errors.WriteError`

Errors every write can fail with, besides the ones its `@throws` documents: `CommonError` and
the errors of signing and sending, also on `.prepare`, `.simulate`, `.estimateGas` and the
`…Sync` form.

```ts
type WriteError = | CommonError | Classes.InsufficientFundsError | Classes.TransactionError | Classes.UnsupportedError | Classes.UserRejectedError | Classes.WalletError;
```

- `WalletError`, or `ConfigError` ([`WALLET_NOT_CONFIGURED`](/docs/sdk/errors/WALLET_NOT_CONFIGURED)), when the wallet cannot sign.
- `UserRejectedError` when the wallet's user declines.
- `InsufficientFundsError` ([`INSUFFICIENT_ETH`](/docs/sdk/errors/INSUFFICIENT_ETH)) when the account cannot pay for gas.
- `UnsupportedError` ([`WALLET_BATCH_UNSUPPORTED`](/docs/sdk/errors/WALLET_BATCH_UNSUPPORTED)) when the wallet cannot send a batch.
- `TransactionError` when a transaction reverts, is replaced, conflicts or is not mined in time.
- A `via` route can also fail with its own package's errors (e.g. `HcaError`).

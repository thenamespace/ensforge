**Write** · Stable · Since 1.0.0

Upgrades the PermissionedResolver of an ENS name to a newer implementation. Resolves once the transaction is submitted.

## When to use

Use to move a name's resolver to the deployment's latest PermissionedResolver implementation. Use [`upgradeSync`](/docs/sdk/reference/actions/resolver/upgrade#wait-for-the-receipt-with-upgradesync) to wait for the receipt.

## Parameters

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `name` (required) | `string` |  | ENS name. Normalized automatically. |
| `implementation` | `string` | the deployment's PermissionedResolver implementation | Implementation to upgrade to. |

Also takes the [write options](/docs/sdk/reference/client#write-options).

## Returns

Resolves to `Write.Result`. Submitted transaction hashes and the plan that produced them.

| Field | Type | Description |
| --- | --- | --- |
| `hash` | `Hex` | Hash of the last transaction. |
| `hashes` | `readonly Hex[]` | Every submitted transaction, in order. |
| `id` | `string` | EIP-5792 bundle id when the calls were sent as one batch. |
| `plan` | `Plan` | The plan the write executed: its steps, in order, as they were submitted. |

## Wait for the receipt with `upgradeSync`

Upgrades the PermissionedResolver of an ENS name to a newer implementation. Resolves once the receipt is in.

Use when the next step depends on the change being on-chain.

`resolver.upgradeSync` takes the same options plus [`confirmations` and `timeout`](/docs/sdk/reference/client#sync-options).

Resolves to `Write.SyncResult`. Receipts plus the submitted hashes and plan.

## Details

- Targets the deployment's current implementation unless `implementation` is given.
- Checks that the target accepts the current implementation (`canUpgradeFrom`) before sending.
- Needs the `upgrade` role on the resolver.

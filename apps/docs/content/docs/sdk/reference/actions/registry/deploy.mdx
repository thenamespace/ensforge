**Write** · Stable · Since 1.0.0

Deploys an ENSv2 UserRegistry, optionally attaching it as a name's subregistry. Resolves once the transaction is submitted.

## When to use

Use to set up the registry for a name's children ahead of time, or with custom roles. Use [`deploySync`](/docs/sdk/reference/actions/registry/deploy#wait-for-the-receipt-with-deploysync) to wait for the receipt.

## Parameters

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `owner` | `string` | the signing account | Account that gets the root roles. |
| `grants` | `readonly { account: string; roles: readonly Role.Name[] \| bigint }[]` |  | Extra root role grants, by role name or bitmap. |
| `emancipated` | `boolean` |  | Withhold the roles that would let the owners take children back. |
| `attachTo` | `string` |  | ENSv2 name to attach it to as subregistry. Normalized automatically. |
| `salt` | `bigint` | a random salt | CREATE2 salt; together with the account it decides the address. |

Also takes the [write options](/docs/sdk/reference/client#write-options).

## Returns

Resolves to `Write.Result & { readonly registry: Address }`. Submitted hashes, the plan and the new registry's address.

## Wait for the receipt with `deploySync`

Deploys an ENSv2 UserRegistry, optionally attaching it as a name's subregistry. Resolves once the receipt is in.

Use when the next step depends on the change being on-chain.

`registry.deploySync` takes the same options plus [`confirmations` and `timeout`](/docs/sdk/reference/client#sync-options).

Resolves to `Write.SyncResult & { readonly registry: Address }`. Receipts, hashes, the plan and the new registry's address.

## Details

- A verifiable proxy of the deployment's UserRegistry, at an address known before sending
  (`plan.deploys`, returned as `registry`).
- `owner` (the signer by default) gets every root role; `emancipated` withholds the roles
  that would let owners take children back.
- `attachTo` makes it that name's subregistry in the same plan.

**Write** · Stable · Since 1.0.0

Approves one address to transfer one ENSv1 name token, or clears the approval. Resolves once the transaction is submitted.

## When to use

Use to let a buyer or escrow take a single name. Use [`setTokenSync`](/docs/sdk/reference/actions/approval/set-token#wait-for-the-receipt-with-settokensync) to wait for the receipt.

## Parameters

| Option | Type | Default | Description |

## Returns

Resolves to `Write.Result`. Submitted transaction hashes and the plan that produced them.

| Field | Type | Description |
| --- | --- | --- |
| `hash` | `Hex` | Hash of the last transaction. |
| `hashes` | `readonly Hex[]` | Every submitted transaction, in order. |
| `id` | `string` | EIP-5792 bundle id when the calls were sent as one batch. |
| `plan` | `Plan` | The plan the write executed: its steps, in order, as they were submitted. |

## Wait for the receipt with `setTokenSync`

Approves one address to transfer one ENSv1 name token, or clears the approval. Resolves once the receipt is in.

Use when the next step depends on the change being on-chain.

`approval.setTokenSync` takes the same options plus [`confirmations` and `timeout`](/docs/sdk/reference/client#sync-options).

Resolves to `Write.SyncResult`. Receipts plus the submitted hashes and plan.

## Details

- Wrapped names approve on the NameWrapper (blocked by `cannotApprove`); unwrapped `.eth`
  names on the BaseRegistrar.
- `to: null` clears it. ENSv2 names use operators instead.

**Write** · Stable · Since 1.0.0

Writes records of an ENS name and resolves once the transaction is submitted.

## When to use

Use to update a profile (texts, addresses, content hash and more) when the UI tracks
confirmation itself. Use [`setSync`](/docs/sdk/reference/actions/record/set#wait-for-the-receipt-with-setsync) to wait for the receipt instead.

| Option | Type | Default | Description |

| `texts` | `Readonly<Record<string, string \| null>>` |  | Text records by key. `null` deletes the record. |
| `addresses` | `Readonly<Record<string, string \| null>>` |  | Address records by coin symbol (`eth`, `btc`) or decimal coin type (`"2147492101"`). `null` deletes the record. |

## Details

- `null` deletes a record.
- All records are written in one `multicall` on the resolver.
- Works with ENSv1 resolvers and the ENSv2 PermissionedResolver; the kind is detected on-chain.
- The records go to the resolver set on the name in its registry, never to a wildcard resolver
  inherited from a parent.
- `resolver` writes the records to another resolver, then points the name at it, in one step:
  a rejected write never leaves the name on an empty resolver.
- Each kind of record is checked against the profiles the resolver declares through ERC-165,
  and `clear` against its record versions, before anything is simulated; a resolver without
  ERC-165 is left to the simulation.
- The plan is simulated before the wallet prompt, so permission errors surface first.

<Callout type="warn" title="Gotchas">

- The ENSv2 PermissionedResolver has no `pubkey` records. `clear` there links the name to record
  0 (needs the root `link` role), so it reads the resolver's default record until new records
  are written.
- Older resolvers lack newer profiles (the 2020 public resolver has no `data` records and cannot
  `clear`), and resolvers that keep their records off-chain (EIP-3668, ERC-5559, ERC-7884) take
  no on-chain writes. Both fail with [`RESOLVER_PROFILE_UNSUPPORTED`](/docs/sdk/errors/RESOLVER_PROFILE_UNSUPPORTED); for an off-chain resolver,
  `details` say where its records live.
- `resolver: "default"` (the ENSv1 public resolver) is for ENSv1 names only; ENSv2 names pass the
  address of a resolver such as their own PermissionedResolver.

</Callout>

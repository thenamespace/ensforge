You will set the **primary name** of an address: the name wallets and apps show instead of `0x…`. It is stored as a **reverse record**, and readers check that the name resolves back to the address (ENSIP-19).

## Prerequisites

- A wallet client for the address you are naming. See [Create a client](/docs/sdk/create-a-client).
- A [name](/docs/reference/glossary#name) that resolves to that address. ensforge checks this before sending and fails with `PRIMARY_NAME_MISMATCH` otherwise. See [Set records](/docs/sdk/set-records).

## 1. Set the primary name on Ethereum

[`primaryName.set`](/docs/reference/sdk/primary-name/set) sets the name for the signer. `primaryName.setSync` also waits for the receipt.

**Example** (Setting Your Primary Name)

```ts title="set-primary-name.ts"
import { http, type Hex } from "viem";
import { privateKeyToAccount } from "viem/accounts";
import { sepolia } from "viem/chains";
import { Ensforge, ensActions } from "@ensforge/sdk";

const ens = Ensforge.create({
  chain: sepolia,
  transports: { [sepolia.id]: http(process.env.SEPOLIA_RPC_URL) },
  account: privateKeyToAccount(process.env.PRIVATE_KEY as Hex),
}).extend(ensActions());

const { hash } = await ens.primaryName.setSync({ name: "ensforge-docs-demo.eth" });
```

Pass `name: null` to clear it. Names with encoded [labels](/docs/reference/glossary#label) (`[af2c…]`) are rejected, because readers show only [normalised](/docs/reference/glossary#normalisation) names.

| Option    | Type                                | Default    | Description                                                             |
| --------- | ----------------------------------- | ---------- | ----------------------------------------------------------------------- |
| `name`    | `string \| null`                    | required   | The primary name, or `null` to clear it.                                |
| `address` | `string`                            | the signer | The address to name. See [Name another address](#name-another-address). |
| `coin`    | `"eth" \| "default" \| { chainId }` | `"eth"`    | Where to set it. See below.                                             |
| `verify`  | `boolean`                           | `true`     | Check that `name` resolves to the address before sending.               |

## 2. Choose where it applies

`coin` picks the chain of the primary name.

| `coin`              | Stored in                      | Applies to                                 |
| ------------------- | ------------------------------ | ------------------------------------------ |
| `"eth"` (default)   | `addr.reverse`                 | Ethereum.                                  |
| `"default"`         | `default.reverse`              | Every EVM chain, as a fallback (ENSIP-19). |
| `{ chainId: 8453 }` | That chain's reverse registrar | That L2 only.                              |

A name in `addr.reverse` outranks `default.reverse` on Ethereum, so `"default"` also sets `addr.reverse` when it holds a different name. A default name whose only address record is an Ethereum address verifies on Ethereum alone. The plan carries a `DEFAULT_PRIMARY_NAME_ETHEREUM_ONLY` warning in that case.

## 3. Set a primary name on an L2

An L2 primary name is a transaction on that L2. The same client sends it there: a local `account` signs through that chain's transport, and a browser `wallet` is asked to switch to the L2 first. Give the L2 a transport for production; without one, ensforge uses its public RPC.

**Example** (Setting a Primary Name on Base Sepolia)

```ts title="set-primary-name-l2.ts"
import { http, type Hex } from "viem";
import { privateKeyToAccount } from "viem/accounts";
import { baseSepolia, sepolia } from "viem/chains";
import { Ensforge, ensActions } from "@ensforge/sdk";

const ens = Ensforge.create({
  chain: sepolia,
  transports: {
    [sepolia.id]: http(process.env.SEPOLIA_RPC_URL),
    [baseSepolia.id]: http(process.env.BASE_SEPOLIA_RPC_URL),
  },
  account: privateKeyToAccount(process.env.PRIVATE_KEY as Hex),
}).extend(ensActions());

await ens.primaryName.setSync({
  name: "ensforge-docs-demo.eth",
  coin: { chainId: baseSepolia.id },
});
```

The plan is for the L2, and resumes there. Readers on Ethereum verify an L2 primary name against the L2's state as committed to Ethereum, so they see it only once that state is, which can take a while after the receipt.

Supported L2s are those with an L2 reverse registrar: OP Mainnet, Base, Arbitrum One, Linea and Scroll, and their Sepolia testnets. Other chains fail with [`UNSUPPORTED_ON_DEPLOYMENT`](/docs/reference/errors/UNSUPPORTED_ON_DEPLOYMENT).

## 4. Set it on several L2s with one signature

[`primaryName.signClaim`](/docs/reference/sdk/primary-name/sign-claim) signs one EIP-191 message that covers several L2s, with no transaction. Anyone can then submit the claim on each chain with `primaryName.set`, so the account needs no gas or wallet connection on the L2s.

**Example** (Signing One Claim for Two Chains)

```ts title="sign-claim.ts"
import { http, type Hex } from "viem";
import { privateKeyToAccount } from "viem/accounts";
import { baseSepolia, optimismSepolia, sepolia } from "viem/chains";
import { Ensforge, ensActions } from "@ensforge/sdk";

const ens = Ensforge.create({
  chain: sepolia,
  transports: { [sepolia.id]: http(process.env.SEPOLIA_RPC_URL) },
  account: privateKeyToAccount(process.env.PRIVATE_KEY as Hex),
}).extend(ensActions());

const signed = await ens.primaryName.signClaim({
  name: "ensforge-docs-demo.eth",
  chainIds: [baseSepolia.id, optimismSepolia.id],
});

await ens.primaryName.set({ ...signed, coin: { chainId: baseSepolia.id } });
await ens.primaryName.set({ ...signed, coin: { chainId: optimismSepolia.id } });
```

- Every mainnet L2 shares one registrar, and testnets share another. One claim cannot mix mainnet chains and testnets, and it cannot include the ENS chain.
- The claim expires `expiresIn` seconds after signing, at most one hour (`3600n`, the default).
- Smart accounts sign as themselves (ERC-1271, or ERC-6492 before they are deployed). The account must exist, or be deployable, on each L2.

### Relay a claim from a server

The claim is plain JSON. The app signs and posts it. A server with a funded wallet on the L2 submits it.

**Example** (Relaying a Signed Claim)

```ts title="relay-claim.ts"
import { http, type Hex } from "viem";
import { privateKeyToAccount } from "viem/accounts";
import { baseSepolia, sepolia } from "viem/chains";
import { Ensforge, ensActions } from "@ensforge/sdk";

const relayer = Ensforge.create({
  chain: sepolia,
  transports: { [baseSepolia.id]: http(process.env.BASE_SEPOLIA_RPC_URL) },
  account: privateKeyToAccount(process.env.RELAYER_PRIVATE_KEY as Hex),
}).extend(ensActions());

export async function relayClaim(body: string) {
  const { claim, signature } = JSON.parse(body);
  return relayer.primaryName.set({ claim, signature, coin: { chainId: baseSepolia.id } });
}
```

`relayer` signs with an account funded on that L2, and pays the gas. Validate the posted body before you submit it. The signature, not the sender, authorises the name.

## Name another address

`address` names another account. The signer must be the address's registry operator or, for a contract, its `Ownable` owner or its ContractNamer. Any other signer fails before sending with [`NOT_APPROVED`](/docs/reference/errors/NOT_APPROVED).

For `"eth"`, a ContractNamer goes through the ENSv2 adapter: it claims the contract's `addr.reverse` node, which makes the signer that node's owner, then sets the name. Those two dependent calls can only be simulated on an RPC that supports `eth_simulateV1`, or with `simulate: false`.

## Check the result

Read it back with [`primaryName.get`](/docs/reference/sdk/primary-name/get). See [Get the name for an address](/docs/sdk/get-a-primary-name).

## Troubleshooting

### `PRIMARY_NAME_MISMATCH`

The name does not resolve to the address. Add an address record with `record.set`, then set the primary name. For an L2, the name needs an address for that chain's coin type or a default EVM address. See [`PRIMARY_NAME_MISMATCH`](/docs/reference/errors/PRIMARY_NAME_MISMATCH).

### `CHAIN_NOT_CONFIGURED`

The client cannot reach the L2: it has no transport for it and `publicRpc` is `false`. Add the L2 to `transports` in `Ensforge.create`. See [`CHAIN_NOT_CONFIGURED`](/docs/reference/errors/CHAIN_NOT_CONFIGURED).

### `INVALID_COIN_TYPE`

`coin` is not an EVM chain, or the claim does not cover the chain. For `signClaim`, `chainIds` is empty, includes the ENS chain, or mixes mainnet and testnets. See [`INVALID_COIN_TYPE`](/docs/reference/errors/INVALID_COIN_TYPE).

### `SIGNATURE_INVALID` or `SIGNATURE_EXPIRED`

The claim's signature does not match, or the claim has expired. Sign again, for the same name, chains and expiry. See [`SIGNATURE_INVALID`](/docs/reference/errors/SIGNATURE_INVALID) and [`SIGNATURE_EXPIRED`](/docs/reference/errors/SIGNATURE_EXPIRED).

### `INVALID_DURATION`

`expiresIn` is not between 1 and 3600 seconds. See [`INVALID_DURATION`](/docs/reference/errors/INVALID_DURATION).

### `NOT_APPROVED`

The signer may not name `address`. See [Name another address](#name-another-address) and [`NOT_APPROVED`](/docs/reference/errors/NOT_APPROVED).

  Setting L2 primary names through an [HCA](/docs/reference/glossary#hca) (`via: hca()`) is not

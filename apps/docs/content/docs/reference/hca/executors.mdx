## Route and executors

### `bundler`

**Experimental**

Runs HCA executions as owner-signed ERC-4337 UserOperations through any bundler, optionally
sponsored by a paymaster. Experimental: the HCA's bundler path has no production proof
upstream yet.

```ts
function bundler(options: BundlerOptions): Executor
```

Use for gasless owner actions (renewals, registration, migration) when the owner holds no ETH; the
owner signs each operation instead of sending a transaction.

- Writes other than registration, migration and `hca.execute` succeed only where the HCA holds
  the roles they need, so transfers and record edits through it usually fail.
- Owner operations only: HCA sessions run through Rhinestone's intent executor, not ERC-4337.
- EntryPoint v0.7; the first operation deploys the HCA through its factory.
- The owner signs with `personal_sign` over the UserOperation hash.

```ts title="A bundler URL"
import { bundler, hca } from "@ensforge/hca"

const via = hca({ executors: [bundler({ url: bundlerUrl, paymaster: bundlerUrl })] })
```

```ts title="Renewing gaslessly"
await ens.registration.renewSync({ names: ["alice.eth"], duration, via })
```

```ts title="With a sponsorship policy"
import { bundler } from "@ensforge/hca"

bundler({ url, paymaster: url, paymasterContext: { sponsorshipPolicyId: "sp_…" } })
```

### `defineExecutor`

**Experimental**

Builds an executor from your own functions, e.g. for another bundler SDK or a relayer.

```ts
function defineExecutor(executor: Executor): Executor
```

Use when none of the built-in executors fits: `send` runs one HCA execution and returns a
reference, `status` reports it.

- Requests carry the HCA, its owner, whether it is deployed, the calls and the session if any.
- Return `{ status: "failed" }` without hashes for executions that never landed: the write can
  send them again.

```ts title="A relayer"
import { defineExecutor } from "@ensforge/hca"

const relayer = defineExecutor({
  id: "relayer",
  capabilities: { sessions: false, sponsorship: true, deploys: false },
  send: async (request) => api.relay(request),
  status: async (id) => api.status(id),
})
```

```ts title="Used for the write"
import { hca } from "@ensforge/hca"

const via = hca({ executors: [relayer] })
```

```ts title="A test double"
import { defineExecutor } from "@ensforge/hca"

const fake = defineExecutor({ id: "fake", capabilities, send: async () => "1", status: async () => ({ status: "success", hashes: [hash] }) })
```

### `hca`

**Experimental**

Sends writes through the signer's ENS Hosted Contract Account (HCA): pass it as `via` to any
write. Steps run as one atomic `executeByOwner` each, the HCA is deployed on first use, and the
approvals it needs to move the owner's names are added as owner transactions.

```ts
function hca(options: HcaOptions = {}): Write.Via
```

Use to migrate several names in one or two transactions instead of one per step, to run writes
gaslessly through a bundler, or prompt-free through a Rhinestone session.

- The HCA runs the calls (`msg.sender`), so it needs authority over what they touch: migration
  and registration plan for it; other writes need the HCA to hold the roles they use.
- With an EIP-5792 wallet the owner's steps (approvals, deployment, executions) share one bundle.
- Never selected implicitly: the user should agree to use their HCA.

```ts title="Migrating through the HCA"
import { hca } from "@ensforge/hca"

await ens.migration.migrateSync({ names: ["alice.eth", "bob.eth"], via: hca() })
```

```ts title="Gasless through a bundler"
import { hca, pimlico } from "@ensforge/hca"

await ens.hca.executeSync({ calls, via: hca({ executors: [pimlico({ apiKey, sponsor: true })] }) })
```

```ts title="Prompt-free with a session"
import { hca, rhinestone } from "@ensforge/hca"

const via = hca({ executors: [rhinestone({ sdk })], session })
await ens.record.set({ name: "alice.eth", texts: { url }, via })
```

### `owner`

**Experimental**

The owner's wallet sends each HCA execution as an `executeByOwner` transaction. The default
executor; needs no service.

```ts
function owner(): Executor
```

Use when the owner pays gas: one transaction per execution, or one EIP-5792 bundle for the
whole write with a wallet that supports it.

- Deploys the HCA with a factory call in the first step when needed.
- With `paymaster` on the write, an EIP-5792 wallet can sponsor the transactions.

```ts title="Explicitly"
import { hca, owner } from "@ensforge/hca"

await ens.hca.executeSync({ calls, via: hca({ executors: [owner()] }) })
```

```ts title="Choosing the executor"
import { hca, owner, pimlico } from "@ensforge/hca"

// `hca()` uses the first executor only, so choose one per request.
const gasless = true
const via = gasless ? hca({ executors: [pimlico({ apiKey })] }) : hca({ executors: [owner()] })
```

```ts title="Sponsored by the wallet"
import { hca } from "@ensforge/hca"

await ens.migration.migrate({ names, via: hca(), paymaster: { url: paymasterUrl } })
```

### `rhinestone`

**Experimental**

Runs HCA executions as Rhinestone intents: owner-signed, or prompt-free with an HCA session.
Experimental; bring a Rhinestone SDK with standalone HCA support.

```ts
function rhinestone(options: RhinestoneOptions): Executor
```

Use for prompt-free registration and record updates with a session (`hca.authorizeSession`),
and for sponsored or stablecoin-paid executions.

- ensforge checks session calls against the HCA policy before anything is signed.
- The SDK account must derive the same HCA address, or the executor fails with
  [`HCA_SDK_UNSUPPORTED`](/docs/reference/errors/HCA_SDK_UNSUPPORTED) (stock SDK releases without the standalone HCA derive another).
- Status follows the intent until its fill transaction is mined.

```ts title="With a session"
import { hca, rhinestone } from "@ensforge/hca"

const via = hca({ executors: [rhinestone({ sdk, sessionSigner })], session })
```

```ts title="Owner-signed, sponsored"
import { hca, rhinestone } from "@ensforge/hca"

const via = hca({ executors: [rhinestone({ sdk })] })
```

```ts title="Paying fees in the refund token"
import { rhinestone } from "@ensforge/hca"

rhinestone({ sdk, sessionSigner, sponsored: false })
```

Deploys the signer's HCA through the ENS factory. Resolves once the transaction is submitted.

## When to use

Use to deploy ahead of time; otherwise the first execution through the HCA deploys it.

## Details

- Idempotent: deploying an existing HCA returns it unchanged.

## Signature

```ts
function deploy(
  client: Like,
  options: deploy.Options & Write.Options,
): Promise<deploy.ReturnType>
```

Call it as `ens.hca.deploy(options)` on a client, or `Actions.hca.deploy(client, options)`.

## Parameters

Also takes the [write options](/docs/reference/sdk/client#write-options).

## Returns

Resolves to `Write.Result`. Submitted transaction hashes and the plan that produced them.

| Field | Type | Description |
| --- | --- | --- |
| `hash` | `Hex` | Hash of the last transaction. |
| `hashes` | `readonly Hex[]` | Every submitted transaction, in order. |
| `id` | `string` | EIP-5792 bundle id when the calls were sent as one batch. |
| `plan` | `Plan` | The plan the write executed: its steps, in order, as they were submitted. |

## Errors

| Error | Codes | When |
| --- | --- | --- |
| [`HcaError`](/docs/reference/errors/hca-error) | [`HCA_UNAVAILABLE`](/docs/reference/errors/HCA_UNAVAILABLE) | on chains without an HCA deployment. |

It can also fail with the errors every write can (`Errors.WriteError`: the common errors plus `InsufficientFundsError`, `TransactionError`, `UnsupportedError`, `UserRejectedError`, `WalletError`).

See [How errors work](/docs/sdk/errors-explained).

## Plan methods

Each method takes the same options as `hca.deploy` and sends nothing. See [Preview before sending](/docs/sdk/preview-before-sending).

| Method | Description |
| --- | --- |
| `hca.deploy.prepare(options)` | Builds the plan without sending anything. |
| `hca.deploy.simulate(options)` | Simulates the plan with `eth_call`, reporting each step. |
| `hca.deploy.estimateGas(options)` | Estimates the gas and ETH the plan needs. |

## Wait for the receipt with `deploySync`

Deploys the signer's HCA through the ENS factory. Resolves once the receipt is in.

Use when the next step depends on the change being on-chain.

`hca.deploySync` takes the same options plus [`confirmations` and `timeout`](/docs/reference/sdk/client#sync-options).

Resolves to `Write.SyncResult`. Receipts plus the submitted hashes and plan.

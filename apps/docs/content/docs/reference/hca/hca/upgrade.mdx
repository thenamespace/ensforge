Upgrades the signer's HCA to an implementation the DAO's upgrade set and its own `canUpgradeFrom` check allow. Resolves once the transaction is submitted.

## When to use

Use when the DAO approves a new HCA implementation; the address and sessions stay.

## Signature

```ts
function upgrade(
  client: Like,
  options: upgrade.Options & Write.Options,
): Promise<upgrade.ReturnType>
```

Call it as `ens.hca.upgrade(options)` on a client, or `Actions.hca.upgrade(client, options)`.

## Parameters

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `implementation` (required) | `string` |  | Implementation to upgrade to. |

Also takes the [write options](/docs/reference/sdk/client#write-options).

## Returns

Resolves to `Write.Result`. Submitted transaction hashes and the plan that produced them.

| Field | Type | Description |
| --- | --- | --- |
| `hash` | `Hex` | Hash of the last transaction. |
| `hashes` | `readonly Hex[]` | Every submitted transaction, in order. |
| `id` | `string` | EIP-5792 bundle id when the calls were sent as one batch. |
| `plan` | `Plan` | The plan the write executed: its steps, in order, as they were submitted. |

## Errors

| Error | Codes | When |
| --- | --- | --- |
| [`HcaError`](/docs/reference/errors/hca-error) | [`HCA_UPGRADE_NOT_ALLOWED`](/docs/reference/errors/HCA_UPGRADE_NOT_ALLOWED) | a DAO set does not allow it. |
| [`InvalidInputError`](/docs/reference/errors/invalid-input-error) | [`INVALID_ADDRESS`](/docs/reference/errors/INVALID_ADDRESS) | an invalid address. |
| [`HcaError`](/docs/reference/errors/hca-error) | [`HCA_UNAVAILABLE`](/docs/reference/errors/HCA_UNAVAILABLE) | on chains without an HCA deployment. |

It can also fail with the errors every write can (`Errors.WriteError`: the common errors plus `InsufficientFundsError`, `TransactionError`, `UnsupportedError`, `UserRejectedError`, `WalletError`).

See [How errors work](/docs/sdk/errors-explained).

## Wait for the receipt with `upgradeSync`

Upgrades the signer's HCA to an implementation the DAO's upgrade set and its own `canUpgradeFrom` check allow. Resolves once the receipt is in.

Use when the next step depends on the change being on-chain.

`hca.upgradeSync` takes the same options plus [`confirmations` and `timeout`](/docs/reference/sdk/client#sync-options).

Resolves to `Write.SyncResult`. Receipts plus the submitted hashes and plan.

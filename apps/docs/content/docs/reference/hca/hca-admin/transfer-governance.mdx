Transfers ownership of the HCA factory (factory owner only). Resolves once the transaction is submitted.

## When to use

Use when governance of HCA deployments moves to another account, e.g. the DAO timelock.

## Signature

```ts
function transferGovernance(
  client: Like,
  options: transferGovernance.Options & Write.Options,
): Promise<transferGovernance.ReturnType>
```

Call it as `ens.hcaAdmin.transferGovernance(options)` on a client, or `Actions.hcaAdmin.transferGovernance(client, options)`.

## Parameters

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `newOwner` (required) | `string` |  | New factory owner. |

Also takes the [write options](/docs/reference/sdk/client#write-options).

## Returns

Resolves to `Write.Result`. Submitted transaction hashes and the plan that produced them.

| Field | Type | Description |
| --- | --- | --- |
| `hash` | `Hex` | Hash of the last transaction. |
| `hashes` | `readonly Hex[]` | Every submitted transaction, in order. |
| `id` | `string` | EIP-5792 bundle id when the calls were sent as one batch. |
| `plan` | `Plan` | The plan the write executed: its steps, in order, as they were submitted. |

## Errors

| Error | Codes | When |

## Wait for the receipt with `transferGovernanceSync`

Transfers ownership of the HCA factory (factory owner only). Resolves once the receipt is in.

Use when the next step depends on the change being on-chain.

`hcaAdmin.transferGovernanceSync` takes the same options plus [`confirmations` and `timeout`](/docs/reference/sdk/client#sync-options).

Resolves to `Write.SyncResult`. Receipts plus the submitted hashes and plan.

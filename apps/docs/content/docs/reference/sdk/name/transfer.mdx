Sends a name to another account and resolves once the transaction is submitted.

## When to use

Use to give a name away or move it between your own accounts. Use [`transferSync`](/docs/reference/sdk/name/transfer#wait-for-the-receipt-with-transfersync) to wait
for the receipt.

## Details

- ENSv2 names move their registry token. With `unsafe`, the transfer also succeeds while other
  accounts still hold roles on the name.
- Wrapped ENSv1 names move their NameWrapper token.
- Unwrapped `.eth` names: `role: "owner"` (default) moves the registrar token and the registry
  ownership (manager); `role: "registrant"` moves only the registrar token.
- Other unwrapped ENSv1 names change their registry owner.
- A name in an L2 namespace moves on its L2, by the client's wallet on that chain: its ERC-721
  token, or Linea Names' NameWrapper token. A Basenames second-level name also moves its
  registry record (`reclaim`) unless `role` is `"registrant"`; a Basenames subname changes its
  registry owner.

<Callout type="warn" title="Gotchas">

- Expired, reserved and unregistered names cannot be transferred.
- ENSv2: roles on the name's PermissionedResolver stay with the sender, who can still edit its
  records (the plan carries a `RECORD_CONTROL_RETAINED` warning). `records: "handover"` grants
  them to the recipient and revokes the sender's in the same step; it is refused for the
  sender's shared `"owned"` resolver, whose roles cover other names.

</Callout>

## Parameters

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `name` (required) | `string` |  | Name to send. Normalized automatically. |
| `to` (required) | `string` |  | Recipient address. |
| `role` | `"owner" \| "registrant"` | `"owner"` | For unwrapped `.eth` names: `owner` moves the registrar token and the manager, `registrant` moves only the registrar token. |
| `unsafe` | `boolean` | `false` | ENSv2 only: transfer even while other accounts hold roles on the name. |
| `records` | `"keep" \| "handover"` | `"keep"` | ENSv2: what happens to the sender's roles on the name's PermissionedResolver. |

Also takes the [write options](/docs/reference/sdk/client#write-options).

## Returns

Resolves to `Write.Result`. Submitted transaction hashes and the plan that produced them.

| Field | Type | Description |
| --- | --- | --- |
| `hash` | `Hex` | Hash of the last transaction. |
| `hashes` | `readonly Hex[]` | Every submitted transaction, in order. |
| `id` | `string` | EIP-5792 bundle id when the calls were sent as one batch. |
| `plan` | `Plan` | The plan the write executed: its steps, in order, as they were submitted. |

## Wait for the receipt with `transferSync`

Sends a name to another account and resolves once the receipt is in.

Use when the next step depends on the new owner being on-chain.

`name.transferSync` takes the same options plus [`confirmations` and `timeout`](/docs/reference/sdk/client#sync-options).

Resolves to `Write.SyncResult`. Receipts plus the submitted hashes and plan.

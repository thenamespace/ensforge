Sends a name to another account and resolves once the transaction is submitted.

## When to use

Use to give a name away or move it between your own accounts. Use [`transferSync`](/docs/reference/sdk/name/transfer#wait-for-the-receipt-with-transfersync) to wait
for the receipt.

## Details

- ENSv2 names move their registry token. The registry allows a safe transfer only when it is
  emancipated and the owner alone holds the name's unemancipated roles; otherwise ensforge sends
  `unsafeTransfer`, which still checks the receiver, with the warning `TRANSFER_UNSAFE` saying
  why. `unsafe: false` fails before sending instead.
- ENSv2: roles other accounts hold on the name stay with them after the move (warning
  `ROLES_RETAINED`). `delegates: "revoke"` revokes them in the same step first: the indexer
  lists the holders, each is checked on chain, and the transfer refuses ([`INDEXER_BEHIND`](/docs/reference/errors/INDEXER_BEHIND)) when
  they do not account for every role. Roles the sender cannot revoke stay, with the warning.
- Wrapped ENSv1 names move their NameWrapper token.
- Unwrapped `.eth` names: `role: "owner"` (default) moves the registrar token and the registry
  ownership (manager); `role: "registrant"` moves only the registrar token.
- Other unwrapped ENSv1 names change their registry owner.
- A name in an L2 namespace moves on its L2, by the client's wallet on that chain: its ERC-721
  token, or Linea Names' NameWrapper token. A Basenames second-level name also moves its
  registry record (`reclaim`) unless `role` is `"registrant"`; a Basenames subname changes its
  registry owner.

- `setEthAddress` points the name's ETH address at the recipient in the same step, before the
  move.
- Giving an ENSv1 subname to another account as its parent's owner is `subname.update({ owner })`.

<Callout type="warn" title="Gotchas">

- Expired, reserved and unregistered names cannot be transferred.
- ENSv2: roles on the name's PermissionedResolver stay with the sender, who can still edit its
  records (the plan carries a `RECORD_CONTROL_RETAINED` warning). `records: "handover"` grants
  them to the recipient and revokes the sender's in the same step. Resolver roles cover every
  name on the resolver, so handover is refused unless the resolver provably serves only this
  name: it is not the sender's or owner's shared `"owned"` resolver, and it holds no record of
  another name. With an indexer, other names pointing at it are refused too; without one, a name
  that points at the resolver but has no records yet cannot be seen.

</Callout>

## Parameters

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `name` (required) | `string` |  | Name to send. Normalized automatically. |
| `to` (required) | `string` |  | Recipient address. |
| `role` | `"owner" \| "registrant"` | `"owner"` | For unwrapped `.eth` names: `owner` moves the registrar token and the manager, `registrant` moves only the registrar token. |
| `unsafe` | `boolean \| "auto"` | `"auto"` | ENSv2: how the token moves. `"auto"` sends a safe transfer when the registry allows one, else `unsafeTransfer` (which still checks the receiver) with the warning `TRANSFER_UNSAFE` saying why; `true` always sends `unsafeTransfer`; `false` fails before sending instead. |
| `delegates` | `"keep" \| "revoke"` | `"keep"` | ENSv2: roles other accounts hold on the name. `"keep"` leaves them (warning `ROLES_RETAINED`); `"revoke"` revokes them before the move, with holders listed by the indexer and checked on chain. |
| `setEthAddress` | `boolean` |  | Write `to` as the name's ETH address on its current resolver first, while the sender still controls it; skipped with the warning `ETH_ADDRESS_NOT_SET` when the sender cannot write there. |
| `records` | `"keep" \| "handover"` | `"keep"` | ENSv2: what happens to the sender's roles on the name's PermissionedResolver. |

Also takes the [write options](/docs/reference/sdk/client#write-options).

## Wait for the receipt with `transferSync`

Sends a name to another account and resolves once the receipt is in.

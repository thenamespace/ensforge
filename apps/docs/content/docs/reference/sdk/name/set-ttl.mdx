Sets the ENSv1 registry TTL of a name. Resolves once the transaction is submitted.

## When to use

Use to change how long resolvers may cache the name's records. Use [`setTtlSync`](/docs/reference/sdk/name/set-ttl#wait-for-the-receipt-with-setttlsync) to wait for the receipt.

## Details

- Wrapped names change their TTL through the NameWrapper.
- ENSv2 has no registry TTL.

## Signature

```ts
function setTtl(
  client: Like,
  options: setTtl.Options & Write.Options,
): Promise<setTtl.ReturnType>
```

Call it as `ens.name.setTtl(options)` on a client, or `Actions.name.setTtl(client, options)`.

## Parameters

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `name` (required) | `string` |  | ENS name. Normalized automatically. |
| `ttl` (required) | `bigint` |  | TTL in seconds. |

Also takes the [write options](/docs/reference/sdk/client#write-options).

## Returns

Resolves to `Write.Result`. Submitted transaction hashes and the plan that produced them.

| Field | Type | Description |
| --- | --- | --- |
| `hash` | `Hex` | Hash of the last transaction. |
| `hashes` | `readonly Hex[]` | Every submitted transaction, in order. |
| `id` | `string` | EIP-5792 bundle id when the calls were sent as one batch. |
| `plan` | `Plan` | The plan the write executed: its steps, in order, as they were submitted. |

## Wait for the receipt with `setTtlSync`

Sets the ENSv1 registry TTL of a name. Resolves once the receipt is in.

Use when the next step depends on the change being on-chain.

`name.setTtlSync` takes the same options plus [`confirmations` and `timeout`](/docs/reference/sdk/client#sync-options).

Resolves to `Write.SyncResult`. Receipts plus the submitted hashes and plan.

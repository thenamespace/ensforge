## Create a client

### `Ensforge.create`

Creates an ensforge client from viem clients.

```ts
function create(options: CreateOptions): Client
```

Use once per chain, at app start, then add action groups with `extend`.

- The deployment is chosen by chain ID (mainnet, Sepolia); other chains need `deployment`.
- `walletClient` can be a getter, so a wallet that connects later works.
- `chains` adds clients for other chains, for the writes ENS makes there: primary names on L2s
  (`primaryName.set` with `coin: { chainId }`).
- The client and its `config` are frozen.

```ts title="Creating a client"
import { Ensforge, ensActions } from "@ensforge/sdk"

const ens = Ensforge.create({ publicClient, walletClient }).extend(ensActions())
```

```ts title="A devnet"
import { Deployments } from "@ensforge/contracts"
import { Ensforge } from "@ensforge/sdk"

const ens = Ensforge.create({
  publicClient: anvil,
  deployment: Deployments.define({ name: "devnet", chainId: 31337, v2: devnetV2 }),
})
```

```ts title="Adding an L2 for primary names"
import { Ensforge, ensActions } from "@ensforge/sdk"

const ens = Ensforge.create({
  publicClient,
  walletClient,
  chains: { 10: { publicClient: optimismClient, walletClient: optimismWallet } },
}).extend(ensActions())

await ens.primaryName.set({ name: "alice.eth", coin: { chainId: 10 } })
```

Errors:

- `ConfigError` ([`UNKNOWN_CHAIN`](/docs/reference/errors/UNKNOWN_CHAIN)) when the chain has no built-in deployment and none is given.
- `ConfigError` ([`INVALID_DEPLOYMENT`](/docs/reference/errors/INVALID_DEPLOYMENT)) when `deployment` is invalid or for another chain.
- `ConfigError` ([`CHAIN_NOT_CONFIGURED`](/docs/reference/errors/CHAIN_NOT_CONFIGURED)) when an entry of `chains` holds clients of another chain.

### `Ensforge.fromWagmi`

Creates an ensforge client from a wagmi config: reads use wagmi's client for the ENS chain, and
writes use whichever wallet is connected when they run.

```ts
function fromWagmi(config: WagmiConfig, options: fromWagmi.Options = {}): Client
```

Use in apps that already have a wagmi config (RainbowKit, ConnectKit, Dynamic, Privy, Reown
AppKit), instead of passing viem clients to `Ensforge.create`.

- Works with wagmi 2 and 3.
- The ENS chain is `chainId`, else mainnet when the config has it, else the first configured
  chain ensforge has a deployment for. Its transport must be in the wagmi config.
- The wallet is looked up on every write, so account and connector changes are followed. With
  no wallet connected, writes fail with [`WALLET_NOT_CONFIGURED`](/docs/reference/errors/WALLET_NOT_CONFIGURED).
- A wallet on another chain is asked to switch first, as wagmi's own `writeContract` does.
- Every other chain of the wagmi config becomes one of the client's `chains`, so writes ENS
  makes there (an L2 primary name) use wagmi's clients and wallet; `chains` adds or overrides.

- `fromWagmi` lives on the `Ensforge` from `@ensforge/sdk/wagmi`, so apps without wagmi never
  load it. The client it returns works with everything in `@ensforge/sdk`.

```ts title="A client for a wagmi app"
import { ensActions } from "@ensforge/sdk"
import { Ensforge } from "@ensforge/sdk/wagmi"

const ens = Ensforge.fromWagmi(wagmiConfig).extend(ensActions())
await ens.record.set({ name: "alice.eth", texts: { url: "https://alice.xyz" } })
```

```ts title="Sepolia, without automatic chain switching"
import { Ensforge } from "@ensforge/sdk/wagmi"

const ens = Ensforge.fromWagmi(wagmiConfig, { chainId: 11155111, switchChain: false })
```

Errors:

- `ConfigError` ([`UNKNOWN_CHAIN`](/docs/reference/errors/UNKNOWN_CHAIN)) when no ENS chain can be chosen or the wagmi config has no transport for it.
- `ConfigError` ([`INVALID_DEPLOYMENT`](/docs/reference/errors/INVALID_DEPLOYMENT)) when `deployment` is invalid or for another chain.
- `ConfigError` ([`CHAIN_NOT_CONFIGURED`](/docs/reference/errors/CHAIN_NOT_CONFIGURED)) when an entry of `chains` holds clients of another chain.

### `Write.Mode`

How a plan's calls are sent: `batch` uses one EIP-5792 wallet call, `sequential` sends one
transaction per call, each once the previous one is mined and with a fifth more gas than
estimated, `auto` batches when the wallet supports atomic batches.

```ts
type Mode = "auto" | "batch" | "sequential";
```

### `Write.Options`

Options every write action takes.


| --- | --- | --- | --- |
| `account` | `Account \| Address` | the client's `account` | Signer for this write. |
| `simulate` | `boolean` | the client's `config.simulate` | Simulate every call before the wallet prompt, so reverts become typed errors first. |
| `signal` | `AbortSignal` |  | Cancels before the next wallet prompt; already submitted transactions are not undone. |

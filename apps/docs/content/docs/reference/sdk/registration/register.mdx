Registers one or more `.eth` names: approve, commit, wait, register, then records and primary name. Resolves once the transaction is submitted.

## When to use

Use to buy names in one flow; the plan runs every transaction in order. Use [`registerSync`](/docs/reference/sdk/registration/register#wait-for-the-receipt-with-registersync) to wait for the receipt.

## Details

- The plan: approve the token (if the allowance is short) with the commit → wait the registrar's
  minimum commitment age on chain time → register (deploying each name's resolver) → records →
  primary name.
- The approval covers the quote plus 2%, since the price is charged at `register` and can drift
  (e.g. a decaying premium); only the actual price is paid.
- Paid in ERC-20 (USDC by default); the registrar does not accept ETH.
- By default a name the signer owns goes on the signer's shared PermissionedResolver (one per
  wallet, at the ENS app's address), deployed once with the first registration; `records` are
  written there after `register`. A name for another owner gets its own PermissionedResolver,
  with `records` written at creation. The ETH address defaults to the owner
  (`addresses: { eth: null }` leaves it unset).
- A primary name is the owner's default name (`default.reverse`); an `addr.reverse` entry with
  another name, which would hide it on Ethereum, is cleared.
- Through `via: hca()` the reveal is one HCA execution: the payment approval, the registrations,
  the shared resolver (deployed by the HCA, writable by the HCA and the owner), its records,
  the primary name, and the approval reset to zero. Only the commit comes before the wait.
- The result's `secret` resumes an interrupted registration: call again with the same options and `secret`.
  A commitment that is not ready yet is waited for; one that expired is made again, with the
  plan warning `COMMITMENT_RECOMMITTED`.

<Callout type="warn" title="Gotchas">

- Resolves after the last transaction is submitted, at least a minute after the commit.
- Resuming needs exactly the same options: they are part of the commitment. A commitment made
  by ensforge 1.1 with the default resolver needs `resolver: "new"` to be revealed; without it
  `register` commits again.

</Callout>

## Parameters

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `names` (required) | `string \| readonly string[]` |  | One or more `.eth` second-level names; several share one plan. Normalized automatically. |
| `duration` (required) | `bigint` |  | Registration length in seconds, e.g. `Duration.years(1)`. |
| `owner` | `string` | the signing account | Owner of the names. |
| `resolver` | `string \| null` | `"owned" for names the signer owns, otherwise "new"` | Resolver for the names. `"owned"` uses the sender's shared PermissionedResolver (the ENS app's address for the wallet or its HCA), deployed once and reused; its roles cover every name on it. `"new"` deploys a PermissionedResolver per name, with `records` written at creation. An address uses that resolver; `null` registers without one. |
| `records` | `Omit<recordSet.Options, "name" \| "resolver" \| "clear" \| "pubkey">` |  | Records for every name, written when its resolver is created (or right after registering). |
| `primaryName` | `boolean` |  | Set the (single) name as the signer's primary name; adds its `eth` address record. |
| `paymentToken` | `PaymentToken` | `"usdc"` | Token to pay with. |
| `subregistry` | `string` |  | ENSv2 registry for the names' subnames. |
| `referrer` | `Hex` |  | Referrer recorded by the registrar: up to 32 bytes of hex, left-padded (an address works). |
| `secret` | `Hex` |  | Secret from an earlier `commit` or `register`, to finish that registration. |

Also takes the [write options](/docs/reference/sdk/client#write-options).

## Wait for the receipt with `registerSync`

Registers one or more `.eth` names: approve, commit, wait, register, then records and primary name. Resolves once the receipt is in.

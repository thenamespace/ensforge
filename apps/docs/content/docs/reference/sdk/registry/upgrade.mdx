Upgrades an ENSv2 registry to the deployment's latest implementation. Resolves once the transaction is submitted.

## When to use

Use to move a subregistry to the current UserRegistry implementation. Use [`upgradeSync`](/docs/reference/sdk/registry/upgrade#wait-for-the-receipt-with-upgradesync) to wait for the receipt.

## Details

- Checks before signing what [`registry.get`](/docs/reference/sdk/registry/get) reports: the `upgrade` root role,
  the target accepting the current implementation (`canUpgradeFrom`), and for emancipated
  registries the upgrade set.

## Returns

Resolves to `Write.Result`. Submitted transaction hashes and the plan that produced them.

| Field | Type | Description |
| --- | --- | --- |
| `hash` | `Hex` | Hash of the last transaction. |
| `hashes` | `readonly Hex[]` | Every submitted transaction, in order. |
| `id` | `string` | EIP-5792 bundle id when the calls were sent as one batch. |
| `plan` | `Plan` | The plan the write executed: its steps, in order, as they were submitted. |

## Wait for the receipt with `upgradeSync`

Upgrades an ENSv2 registry to the deployment's latest implementation. Resolves once the receipt is in.

Use when the next step depends on the change being on-chain.

`registry.upgradeSync` takes the same options plus [`confirmations` and `timeout`](/docs/reference/sdk/client#sync-options).

Resolves to `Write.SyncResult`. Receipts plus the submitted hashes and plan.

Reads a saved plan and its progress.

## When to use

Use to show where a registration, migration or other multi-step write stands.

## Details

- Every write saves its plan to the client's `storage` as it sends.
- `null` when no plan has the id (memory storage forgets plans on reload).

## Signature

```ts
function get(client: Like, options: get.Options): Promise<get.ReturnType>
```

Call it as `ens.plan.get(options)` on a client, or `Actions.plan.get(client, options)`.

`plan.get.request(options)` builds a deferred read for `Actions.batch`. See [Look up many at once](/docs/sdk/look-up-many-at-once).

## Parameters

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `id` (required) | `string` |  | Plan id, from `result.plan.id` or a failure's `context.planId`. |

## Returns

Resolves to `Plan.Record | null`. The saved plan and its progress, or `null`.

| Field | Type | Description |
| --- | --- | --- |
| `plan` | `Plan` |  |
| `status` | `"pending" \| "completed" \| "failed"` | `pending` while steps remain, `completed` once every step is submitted. |
| `submitted` | `Readonly<globalThis.Record<string, readonly Hex[]>>` | Transaction hashes per submitted step id. |
| `bundles` | `Readonly<globalThis.Record<string, string>>` | EIP-5792 bundle id per step sent in a bundle. |
| `references` (optional) | `Readonly<globalThis.Record<string, string>>` | Route references per step sent through `via` (e.g. UserOperation hashes). |
| `error` (optional) | `string` | Message of the last failure. |
| `updatedAt` | `number` | Unix time in milliseconds. |

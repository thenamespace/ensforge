Grants ENSv2 roles to an account on a name, or at the root of a registry or resolver. Resolves once the transaction is submitted.

## When to use

Use to delegate specific powers, such as renewing or changing the resolver, without transferring a name. Use [`grantSync`](/docs/reference/sdk/role/grant#wait-for-the-receipt-with-grantsync) to wait for the receipt.

## Details

- Name roles go to the name's resource in the registry holding it; root roles apply to every
  name in that registry or on that resolver.
- Granting needs the matching admin roles.
- Some roles regenerate the name's token ID; the plan carries a `TOKEN_ID_REGENERATED` warning.

<Callout type="warn" title="Gotchas">

- `renew` granted on a name lets its holder renew it only in registries that predate
  contracts-v2 #505; the deployment's current UserRegistry checks it at the root (`root: true`).

</Callout>

## Parameters

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `grantee` (required) | `string` |  | Account that gets the roles. |
| `roles` (required) | `readonly Role.Name[] \| bigint` |  | Roles by name, e.g. `["setResolver"]`, or as a bitmap. |
| `target` (required) | `"registry" \| "resolver"` |  | Registry or PermissionedResolver roles (resolvers: root only). |
| `name` | `string` |  | ENS name whose registry or resolver to use. Normalized automatically. |
| `contract` | `string` |  | Registry or resolver address, instead of the name's. |
| `root` | `boolean` |  | Root roles, applying to every name, instead of the name's. |

Also takes the [write options](/docs/reference/sdk/client#write-options).

## Wait for the receipt with `grantSync`

Grants ENSv2 roles to an account on a name, or at the root of a registry or resolver. Resolves once the receipt is in.

Use when the next step depends on the change being on-chain.

`role.grantSync` takes the same options plus [`confirmations` and `timeout`](/docs/reference/sdk/client#sync-options).

Resolves to `Write.SyncResult`. Receipts plus the submitted hashes and plan.

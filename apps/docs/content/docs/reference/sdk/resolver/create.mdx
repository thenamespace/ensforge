Deploys an ENSv2 PermissionedResolver, optionally with records, and points a name at it. Resolves once the transaction is submitted.

## When to use

Use to give an ENSv2 name its own resolver, or to set up a resolver shared by several names. Use [`createSync`](/docs/reference/sdk/resolver/create#wait-for-the-receipt-with-createsync) to wait for the receipt.

## Details

- The resolver is a verifiable proxy from the VerifiableFactory; its address is known before
  sending (`plan.deploys`) and returned as `resolver`.
- `owner` (the signer by default) gets every role; `grants` add more accounts.
- Through `via` (an HCA), the route's account deploys the resolver, and it and the signer both
  get every role.
- With `name`, `records` are written during initialization and the name is pointed at the
  new resolver in the same plan.

<Callout type="warn" title="Gotchas">

- The address depends on the sending account (the route's account through `via`) and `salt`:
  send from the account the plan was prepared for. A `salt` already used by that account fails with [`SALT_TAKEN`](/docs/reference/errors/SALT_TAKEN), whose
  `context.contract` is the existing resolver; point the name at it with `resolver.set`.

</Callout>

## Parameters

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `name` | `string` |  | Name to point at the new resolver; required for `records`. Normalized automatically. |
| `records` | `Omit<recordSet.Options, "name" \| "resolver" \| "clear" \| "pubkey">` |  | Records for `name`, written while the resolver is initialized. |
| `owner` | `string` | the signing account | Account that gets every resolver role. |
| `grants` | `readonly { account: string; roles: readonly Role.Name[] \| bigint }[]` |  | Extra role grants, by role name or bitmap. |
| `salt` | `bigint` | a random salt | CREATE2 salt; together with the account it decides the address. |

Also takes the [write options](/docs/reference/sdk/client#write-options).

## Returns

Resolves to `Write.Result & { readonly resolver: Address }`. Submitted transaction hashes, the plan and the new resolver's address.

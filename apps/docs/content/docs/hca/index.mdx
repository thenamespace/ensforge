By the end of this page you will have migrated two names in one HCA execution and read the account that ran it. Install the package first: [Installation](/docs/hca/installation).

## 1. Create the client

Add `hcaActions()` to a client that has a wallet. Use Sepolia and names your wallet owns.

```ts twoslash title="client.ts"
import { hcaActions } from "@ensforge/hca";
import { Ensforge, ensActions } from "@ensforge/sdk";
import { createPublicClient, createWalletClient, http } from "viem";
import { privateKeyToAccount } from "viem/accounts";
import { sepolia } from "viem/chains";

const account = privateKeyToAccount(
  "0x0123456789012345678901234567890123456789012345678901234567890123",
);

export const ens = Ensforge.create({
  publicClient: createPublicClient({ chain: sepolia, transport: http() }),
  walletClient: createWalletClient({ account, chain: sepolia, transport: http() }),
})
  .extend(ensActions())
  .extend(hcaActions());
```

## 2. Send a write through the HCA

Pass `via: hca()` to any write. `hca()` is a route: it rewrites the write's plan so that the HCA runs the calls. ensforge never selects it on its own, so the user agrees to it through the code you write.

**Example** (Migrating Two Names Through the HCA)

```ts twoslash title="migrate.ts"
import { hca, hcaActions } from "@ensforge/hca";
import { Ensforge, ensActions } from "@ensforge/sdk";
import { createPublicClient, createWalletClient, http } from "viem";
import { privateKeyToAccount } from "viem/accounts";
import { sepolia } from "viem/chains";

const account = privateKeyToAccount(
  "0x0123456789012345678901234567890123456789012345678901234567890123",
);
const ens = Ensforge.create({
  publicClient: createPublicClient({ chain: sepolia, transport: http() }),
  walletClient: createWalletClient({ account, chain: sepolia, transport: http() }),
})
  .extend(ensActions())
  .extend(hcaActions());
// ---cut---
const result = await ens.migration.migrateSync({
  names: ["alice.eth", "bob.eth"], // placeholders: use names you own
  via: hca(),
});

console.log(result.plan.steps.map((step) => step.id));
```

With the default executor your wallet sends every transaction:

1. The HCA is deployed on first use.
2. The approvals it needs to move your names run as one owner step named `hca-setup`.
3. Both migrations run as one atomic `executeByOwner` call, so either every name moves or none does.

With an EIP-5792 wallet, the owner's steps share one bundle. See [Your wallet](/docs/hca/your-wallet).

## 3. Read the account

`ens.hca.get` reads the HCA's address, owner, implementation and any problems. It works before deployment, using the predicted address.

```ts twoslash title="get-account.ts"
import { hcaActions } from "@ensforge/hca";
import { Ensforge, ensActions } from "@ensforge/sdk";
import { createPublicClient, createWalletClient, http } from "viem";
import { privateKeyToAccount } from "viem/accounts";
import { sepolia } from "viem/chains";

const account = privateKeyToAccount(
  "0x0123456789012345678901234567890123456789012345678901234567890123",
);
const ens = Ensforge.create({
  publicClient: createPublicClient({ chain: sepolia, transport: http() }),
  walletClient: createWalletClient({ account, chain: sepolia, transport: http() }),
})
  .extend(ensActions())
  .extend(hcaActions());
// ---cut---
const hcaAccount = await ens.hca.get({});
//    ^?
```

`problems` is empty for an account that is safe to use. See [`hca.get`](/docs/hca/reference/actions/hca/get).

<Callout type="warn" title="The HCA is msg.sender">
  Through `via: hca()` the HCA, not your wallet, calls the contracts. Migration and registration
  plan for that. Other writes, such as records or transfers, work only where the HCA holds the roles
  they need, and fail at simulation otherwise.
</Callout>

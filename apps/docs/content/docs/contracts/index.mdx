By the end of this page you will have read a name's registry state from the ENSv2 `.eth` registry with viem, using an ABI and an address from `@ensforge/contracts`. Install the package first: [Installation](/docs/contracts/installation).

## 1. Pick an address and an ABI

`Deployments.mainnet.v2.contracts.ethRegistry` is the address of the registry that holds `.eth` names. `Abis.v2.permissionedRegistry` is the ABI to read it with. The ABI is an `as const` array, so viem infers the function names, arguments and return types.

## 2. Read the contract

`getState` takes a label's hash as a number and returns the name's status, expiry, latest owner, token ID and role resource.

**Example** (Reading a Name's State)

```ts twoslash title="get-state.ts"
import { Abis, Deployments } from "@ensforge/contracts";
import { createPublicClient, hexToBigInt, http } from "viem";
import { labelhash } from "viem/ens";
import { mainnet } from "viem/chains";

const publicClient = createPublicClient({ chain: mainnet, transport: http() });

const state = await publicClient.readContract({
  address: Deployments.mainnet.v2.contracts.ethRegistry,
  abi: Abis.v2.permissionedRegistry,
  functionName: "getState",
  args: [hexToBigInt(labelhash("vitalik"))],
});

state;
// ^?
```

- `labelhash("vitalik")` hashes the label (the part before `.eth`). Normalise a label before you hash it.
- `status` is the contract's `Status` enum, returned as a number: `AVAILABLE`, `RESERVED` or `REGISTERED`.

## 3. Read another chain

`Deployments.sepolia` has the same shape. Use `Deployments.get({ chainId })` when the chain comes from a variable.

```ts twoslash title="by-chain.ts"
import { Deployments } from "@ensforge/contracts";

const profile = Deployments.get({ chainId: 11155111 });
const ethRegistry = profile?.v2?.contracts.ethRegistry;
```

`get` returns `undefined` for a chain ensforge does not ship. See [Addresses and chains](/docs/contracts/addresses-and-chains).
